# Associative Research — 发散式调研引擎

## 一、核心理念

**关键词陷阱**：用已知的词汇搜索，只能找到已知概念框架内的东西。
当信息藏在：另一个领域的术语里 / 上下游的视角里 / 问题的反面 / 相邻概念的交叉处——
直接搜索就会失效。

本 skill 的本质是**在搜索之前先做概念地图**，在陷入死胡同之后能**有意识地跳跃**。

---

## 二、触发判断（1% 规则）

> 引用自 obra/superpowers：哪怕只有 1% 的概率本 skill 适用，也应先加载它来判断。

满足以下任一条件，激活本 skill：
- 连续搜索 ≥2 次，结果标题/来源高度重叠
- 问题涉及 2 个以上不同领域的交叉
- 用户描述的场景是"我知道这个东西存在，但就是搜不到"
- 调研目标是新技术、新产品、新想法（成熟关键词尚未形成）

## 四、关键机制详解

### 机制 A：概念地图构建（搜索前必做）

在第一次搜索之前，先回答这三个问题：

```
1. 这个东西的「本质」是什么？
   （剥离掉现有的名称和形态，它在解决什么问题？）

2. 谁还在解决同一个「本质问题」，但用的是不同名称？
   （换行业 / 换语言 / 换时间段）

3. 这个东西处于哪条价值链的哪个位置？
   （它的上游是什么？下游是什么？替代品是什么？）
```

**示例**：调研「LLM Agent 的记忆管理方案」
- 本质：跨会话的状态持久化 + 选择性召回
- 换名称搜索：session state management / episodic memory / working memory architecture
- 上游：context window 管理；下游：agent personalization；替代品：external KV store

---

### 机制 A2：查询变体（轻量）

在概念地图之后，不要只搜 1 个产品词。
至少换 2-3 个视角试一下：

- 问题本身：用户到底在解决什么
- 机制原理：这个问题通常怎么实现
- 失败/反对：为什么有人不用它
- 替代/迁移：从什么迁到什么
- 跨语言/跨领域：别的圈子怎么叫它

不要求维护复杂日志，只需要简短记住：
- 哪类词已经试过
- 哪个词带来了新实体/新术语
- 下一步准备往哪里 pivot

---

### 机制 B：五种跳跃策略（死胡同时选一种）

当直搜失效，按以下顺序尝试：

| 策略 | 触发条件 | 操作 | 示例 |
|------|---------|------|------|
| **① 同义替换** | 术语不统一 | 换行业术语 / 英文 / 缩写 / 学术词 | "工单系统" → "ticketing system" / "ITSM" |
| **② 上游视角** | 直搜只有产品，没有原理 | 搜「这个东西是用什么做的」 | 搜不到 X 框架 → 搜"X 框架底层依赖的核心库" |
| **③ 下游视角** | 直搜太抽象 | 搜「用这个东西能做什么」 | 搜不到 RAG 架构 → 搜"企业知识库 AI 产品怎么做的" |
| **④ 问题反转** | 搜方案没结果 | 搜「这个问题的失败案例 / 踩坑记录」 | 搜不到最佳实践 → 搜"XXX 有什么坑 / 为什么不用 XXX" |
| **⑤ 跨域类比** | 新概念，行业内无先例 | 找「其他行业用什么解决了结构相似的问题」 | Agent 工作流调度 → 找"分布式任务队列的调度策略" |

> 每次只选一种策略，执行完再评估是否需要下一种。不要同时用多种——会产生噪音。

---

### 机制 C：蛛丝马迹追踪

> 最有价值的信息往往藏在「不期而遇的搜索结果」里。

当搜索结果中出现以下信号，**不要跳过，立刻追踪**：

- 一篇你没预期领域的文章，但标题或摘要包含你关心的概念
- 一个评论区 / issue / HN 讨论里有人提到了一个你没见过的词
- 搜索结果里有一个项目，它的 README 「Related Projects」部分列了很多你不认识的名字
- 一篇批评文章，批评的对象是你正在调研的东西

**追踪操作**：
```
1. 记录这个意外信号（是什么、在哪出现的）
2. 以这个信号为新起点，单独做一轮搜索
3. 如果这轮搜索产出了有价值信息 → 纳入证据池
4. 如果没有 → 标记为「弱信号/待验证」，继续主线
```

---

### 机制 D：轻量校验

这个 skill 的重点是“找到东西”，不是把自己变成审计系统。
但有三条底线还是要有：

- 关键结论尽量别只靠一种来源
- 主题变化很快时，顺手看一下最近 release / changelog / 社区讨论
- 如果两个来源打架，不要强行抹平，直接标成「待验证」

## 五、死胡同反模式

> 参考 deanpeters/Product-Manager-Skills 的 Symptom/Consequence/Fix 格式

**反模式 1：关键词复读机**
- 症状：搜索词只是原词的同义词替换，或增减形容词（如 "best X" / "top X" / "X tutorial"）
- 后果：搜索结果同质化，越搜越窄
- 修复：强制切换到「上游视角」或「问题反转」策略

**反模式 2：锚定第一页**
- 症状：只看搜索结果前 3 条，认为没有相关内容就放弃
- 后果：错过藏在边缘的高价值信号
- 修复：至少翻到第 2 页，专门找「不太对但有点像」的结果

**反模式 3：忽略意外命中**
- 症状：搜索结果里出现了一个意外的名词 / 项目 / 概念，但因为「不在预期内」而跳过
- 后果：最有价值的跨域线索就藏在这里
- 修复：激活蛛丝马迹追踪机制（见机制 C）

**反模式 4：只搜中文**
- 症状：调研新技术 / 新概念，全程只用中文搜索
- 后果：中文内容滞后英文 6-18 个月，等于调研了历史
- 修复：对技术类调研，中英文并行搜索；英文结果优先作为第一手来源

**反模式 5：过早收敛**
- 症状：刚找到一个看起来合理的解释，就停止继续扩展搜索空间
- 后果：会把最先命中的概念当成唯一答案，错过更优路径
- 修复：在下结论前，至少再换一次视角或来源，确认不是偶然命中

## 六、输出格式

### 调研报告（Markdown）

```markdown
# [主题] 调研报告

## TL;DR
（2-3 句话：核心结论是什么）

## 调研路径记录
（用了哪些搜索策略，哪里发生了 pivot，哪些线索是意外挖出来的）
— 这部分是本 skill 特有的，让用户理解调研思路，便于后续深挖

## 主要发现

### [方向 1]
...

### [方向 2]
...

## 对比矩阵
（见下）

## 不确定性 & 待验证
（明确标出哪些信息是推测/弱信号，还没有充分验证）

## 延伸线索
（调研过程中发现的意外有趣方向，未深挖）
```

### 对比矩阵（Table）

根据调研主题动态生成维度，不使用固定模板。
维度由调研过程中发现的「真正重要的差异点」决定，而不是预设的通用维度。

## 七、与其他 skill 的配合

本 skill 是**调研底层引擎**，产出的原材料可以喂给：
- `tech-stack-scout`：当调研对象是技术选型时，把本 skill 的发现作为候选池输入
- `product-landscape`：当调研对象是产品/市场格局时，把本 skill 的发现作为竞品池输入
- `idea-validation`：当调研是为了验证一个想法时，把本 skill 的结论作为「已有解法扫描」输入
