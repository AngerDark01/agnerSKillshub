# Product Landscape — 产品/市场格局调研

## 一、视角声明

本 skill 面向**工程师 / 独立开发者 / 技术负责人**，不是 PM。

调研目的通常是以下之一：
- **做还是不做**：这个方向有没有过于强势的竞争对手，还有没有做的空间？
- **怎么做参考**：竞品的技术方案是什么，有什么值得借鉴 / 避开的？
- **差异化定位**：现有产品普遍做不好哪里，我的切入点在哪？

---

## 二、调研流程

### Phase 0：锁定调研目的（先于搜索）

```
□ 我在做 / 想做什么？（一句话描述）
□ 调研的目的是什么？（做决策 / 找参考 / 了解格局）
□ 我的目标用户是谁？（有没有特定的细分市场）
□ 我有哪些约束？（资源 / 技术 / 时间）
```

---

### Phase 0.5：先搜用户任务，不先搜产品名

产品调研很容易被现有类目词绑架。先把问题改写成这些搜索视角：

```markdown
1. 用户在完成什么任务？
2. 用户现在用什么替代方式凑合解决？
3. 用户最常抱怨什么？
4. 谁在卖同一个结果，但不一定用同一个品类名称？
```

先从任务和痛点搜，再回到产品名，更容易发现间接竞品和替代品。

---

### Phase 1：市场全景扫描

**目标**：在不遗漏主要玩家的前提下，建立分层视图。

**分层结构**：
```
头部玩家（市场认知度最高，通常是行业默认答案）
    ↓
垂直玩家（聚焦某个细分，或某类用户）
    ↓
新兴玩家（过去 1-2 年出现，增长明显）
    ↓
开源 / 自建替代（不是商业产品，但解决同一问题）
```

**搜索策略 —— 内嵌 associative-research 跳跃**：

直搜通常只能找到头部玩家。要找全，需要跳跃：

| 跳跃方式 | 操作 |
|---------|------|
| 搜用户讨论 | Reddit / HN / v2ex 搜「[问题描述]，用什么好」 |
| 搜替代品聚合 | alternativeto.net / producthunt.com 搜主竞品 |
| 搜失败故事 | "why I left X" / "X 的问题" → 可能提到用户转向了什么 |
| 搜开源生态 | GitHub topic 搜核心概念 → 找到可能未商业化的方案 |
| 搜上下游 | 找「集成了 X 的产品」/ 「依赖 X 的公司」，可能是间接竞品 |
| 蛛丝马迹追踪 | 某个竞品的 changelog / roadmap 里提到了哪些它在对抗的方向 |

除此之外，主动换 3-5 个搜索视角：

```markdown
□ 品类词：这个市场通常怎么命名？
□ 任务词：用户到底想完成什么？
□ 抱怨词："why X sucks" / "alternative to X" / "how people solve Y"
□ 替代路径：服务、模板、咨询、开源、自建脚本是否都在解决同一个问题？
□ 跨语言/跨地区：英文市场和中文市场是否用不同术语或卖点？
```

弱信号来源尤其值得追：
- 定价页突然变化
- 集成目录新增某类集成
- roadmap / changelog 中频繁出现同一方向
- 招聘 JD 透露出目标客户或技术路线

---

### Phase 2：竞品深度拆解

对每个重点竞品（3-5 个），回答以下问题：

```
□ 核心功能是什么？（它真正在解决什么问题，不是官网说什么）
□ 目标用户是谁？（从定价 / 文档 / 案例反推）
□ 商业模式？（免费增值 / 订阅 / 按量 / 开源商业化）
□ 技术架构特点？（如果能从文档 / 开源代码推断）
□ 用户真实反馈？（社区评论 / App Store 差评 / HN 讨论）
□ 它的明显局限是什么？（用户在哪里抱怨它）
□ 近期动向？（最近做了什么，在往哪个方向走）
```

> **用户真实反馈** 是最有价值的，比官方描述更真实。
> 重点看：差评、迁移故事、"我不用 X 因为……"

---

### Phase 2.5：轻量校验

对重点竞品，至少顺手补三类材料：

- 官网/定价/文档：它自己怎么定位
- 用户反馈：差评、讨论、迁移故事
- 近期动向：最近 6-18 个月在增强什么、放弃什么

如果官方宣传和用户反馈冲突，不要替它圆，直接写出来。

---

### Phase 3：空白与机会识别

调研完竞品后，问这三个问题：

```
1. 现有产品普遍做不好的地方是什么？
   （多个竞品的共同弱点 = 市场机会）

2. 有没有被忽视的用户群体？
   （谁的需求没有被主流产品很好地服务？）

3. 有没有因为技术变化而出现的新窗口？
   （某项新技术的出现让旧方案变得过时？）
```

---

### Phase 4：结论生成

```markdown
## 市场格局概览

[2-3 句话：谁是主导者，市场处于什么阶段，整体竞争程度]

## 竞品对比矩阵

| 产品 | 目标用户 | 核心优势 | 核心局限 | 定价模式 |
|------|---------|---------|---------|---------|
| ... | ... | ... | ... | ... |

（维度根据调研发现动态生成，不强制使用上面这个模板）

## 空白 & 机会

[如果是做决策：这个方向值不值得做，理由是什么]
[如果是找参考：竞品哪些方案值得借鉴，哪些要避开]
[如果是找定位：差异化切入点在哪里]

## 不确定性

[哪些竞品信息未能验证，哪些结论是推测]

## 延伸线索

[调研过程中发现的意外方向，未深挖]
```

## 三、反模式

**反模式 1：只看头部竞品**
- 症状：调研报告里只有 3-5 个大家都知道的产品
- 后果：错过新兴玩家和开源替代，也看不出差异化空间
- 修复：强制执行 Phase 1 的跳跃搜索，特别是「搜替代品聚合」和「搜用户讨论」

**反模式 2：只看官网 Feature List**
- 症状：对比表全是功能打勾，没有任何用户视角的评价
- 后果：看不到真实的产品体验和局限
- 修复：对每个重点竞品，必须找到至少一条来自真实用户的批评性评价

**反模式 3：把「没有竞品」当好事**
- 症状：搜不到竞品，认为这是市场空白
- 后果：可能是市场太小 / 需求不真实 / 已有人做过但失败了
- 修复：「搜不到」时激活 associative-research 的死胡同跳跃策略；同时搜「为什么没有人做 X」

**反模式 4：工程师视角缺失**
- 症状：调研报告全是业务功能对比，没有技术层面的分析
- 后果：对「怎么做」没有参考价值
- 修复：对每个竞品，尝试从文档 / 开源代码 / 技术博客中推断其技术架构选择

**反模式 5：把类目词当成市场边界**
- 症状：只搜你脑海里那个品类名称，例如"AI note app"
- 后果：会漏掉卖同样结果、但用完全不同定位的话术和产品
- 修复：回到用户任务、替代行为、失败故事、跨地区术语重新展开

## 四、调用关系

本 skill 依赖 `associative-research` 的跳跃机制（Phase 1）。
如果调研目的是选一个具体的技术工具，改用 `tech-stack-scout`。
两个 skill 可以组合使用：先用本 skill 了解市场格局，再用 `tech-stack-scout` 做具体方案评估。
