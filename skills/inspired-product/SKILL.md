# Inspired Product — Empowered Teams Framework

Apply Marty Cagan's principles from *INSPIRED* to build products through empowered, outcome-oriented teams.

## Core Model: Dual-Track

Run **Discovery** and **Delivery** in parallel — never sequentially.

```
Discovery Track  ──▶  Validate ideas quickly (days/weeks)
                         ↓ only validated ideas pass
Delivery Track   ──▶  Build shippable software (sprints)
```

**Discovery goal**: Reduce risk before spending engineering time.
**Delivery goal**: Ship reliable, high-quality software.

## The Four Product Risks

Every product idea carries four risks. All must be addressed before building:

| Risk | Question | Validated by |
|------|----------|--------------|
| **Value risk** | Will customers buy / use it? | Customer interviews, prototypes |
| **Usability risk** | Can customers figure out how to use it? | Usability testing |
| **Feasibility risk** | Can we build it? | Engineering spike / prototype |
| **Viability risk** | Does it work for our business? | Business/legal/stakeholder review |

Complete a risk table for every significant opportunity before committing to build.

## Opportunity Assessment

Before starting discovery on any initiative, answer these 10 questions:

1. What problem are we solving? (exact customer quote if possible)
2. For whom? (specific customer segment)
3. What evidence do we have this is a real problem? (frequency, severity)
4. What does success look like? (measurable outcome)
5. What's the current workaround? (non-obvious competition)
6. Why now? (urgency, window of opportunity)
7. Why us? (unique position to solve this)
8. What are the risks? (value / usability / feasibility / viability)
9. What's the smallest thing we can build to test our hypothesis?
10. How will we know when we're done?

## Product Vision and OKRs

**Product Vision** (3–5 year horizon): An inspiring, customer-centric picture of the future — not a roadmap, not a feature list.

**OKR format** (quarterly):
```
Objective: [Qualitative, inspiring goal]
  Key Result 1: [Measurable outcome metric]
  Key Result 2: [Measurable outcome metric]
  Key Result 3: [Measurable outcome metric]
```

**Rules:**
- KRs are outcomes, never outputs ("revenue grows 20%", not "ship feature X")
- Teams own KRs, not tasks assigned by managers
- Initiatives are teams' chosen approaches — not prescribed by leadership

## Discovery Techniques (Quick Reference)

| Technique | Risk addressed | Time |
|-----------|---------------|------|
| Customer interview | Value | 30–60 min |
| Prototype (paper/hi-fi) | Usability | 1–3 days |
| Concierge MVP | Value + Feasibility | 1–2 weeks |
| A/B test | Value | 1–4 weeks |
| Engineering spike | Feasibility | 1–5 days |
| Stakeholder review | Viability | 1–2 hours |

## Team Topology

**Empowered product team** (minimum viable team):
- 1 Product Manager (problem authority)
- 1 Product Designer (usability authority)
- 2–8 Engineers (feasibility authority)

**PM's job**: Understand customers deeply enough to define the right problems. NOT to write requirements and hand them to engineering.

## Deliverables Checklist

- [ ] Risk table (4 risks assessed with evidence)
- [ ] Opportunity assessment (10 questions answered)
- [ ] Discovery experiment plan (hypothesis → test → metric)
- [ ] Product vision statement (3–5 year)
- [ ] Quarterly OKRs (outcomes, not outputs)
