# Mode: rule_generated

## 适用场景

- 招标文件没有稳定模板，或模板不适合直接复用。
- 本章核心是按业务规则、第一阶段结果和当前项目约束生成正文。
- 文字结构比版式模板更重要。

常见章节：按评分点生成的技术说明、按规则生成的符合性应答、需根据上游结构化结果重写的说明段。

## 必读输入

- 当前章节对应的招标条款。
- 第一阶段结构化结果。
- 技术规范书或商务约束。
- 企业模板、知识库或历史成熟模块。

## 标准动作

1. 读取本章依赖的条款、规则和结构化结果。
2. 先确定本章要回答哪些问题。
3. 再按统一格式生成正文、子节或说明。
4. 如需证据材料，再追加挂载位置或引用说明。
5. 回写生成依据、未决点和输出文件。

## 特殊规则

- `rule_generated` 不等于自由发挥写作。
- 生成内容必须受招标条款、评分点、第一阶段结果和已有资料约束。
- 对结论性符合性判断，若用户已有默认口径且未发现反证，直接输出 `满足`、`符合`、`无相关情形`，不留 `用户填写` 槽位。
- 不确定的参数、时效性内容、个人信息和证照信息不能猜写。
- 如果后续还需要并入大章节，可先产出 `child_partial`。
- 技术服务、培训、制造工艺等章节，默认还要受技术规范书和知识库约束，不从空白页自由扩写。
- 制造商说明等固定话术场景，可复用稳定表述，但不得伪造实时签订的授权协议、第三方函件或客观检测数据。

## Done 条件

- 每段核心结论都有来源或依据类别。
- 默认满足口径只用于结论性判断，不用于硬事实。
- 缺失材料、参数或证照有 pending 标注。
- 生成正文已写入章节 partial 或目标文档。
