# Mode: module_docx

## 适用场景

- 已有成熟的整章 DOCX 模块。
- 模块内容和当前项目章节语义高度一致。
- 直接复用比从零切模板更稳定。

常见章节：`投标人基本情况表`、`财务状况`、成熟技术方案模板。

## 必读工具

- DOCX 结构检查：`../../../autobid-office-tools/references/docx-inspect.md`
- 版式复制和统一：`../../../autobid-office-tools/references/docx-layout.md`
- 合并：`../../../autobid-office-tools/references/docx-merge.md`
- 打包校验：`../../../autobid-office-tools/references/docx-pack.md`

## 标准动作

1. 先确认模块与当前 `输出章节模板` 语义一致。
2. 判断它是单章输出还是一个大章节的最终维护单位。
3. 检查模块标题、模块开头和章节号是否符合当前招标文件。
4. 区分图片主体与文本/表格正文，决定哪些直接复用、哪些必须重填。
5. 直接套用可复用模块正文。
6. 统一当前项目的页眉页脚、logo、页边距、标题字体和表格格式。

## 特殊规则

- `module_docx` 直套，不等于跳过格式规范。
- 模块里原有章节编号和说明文字不能直接信任，仍需对齐当前项目。
- 如果模块大部分由图片或扫描件拼接而成，优先直接复用图片主体，不重做图片区。
- 图片之外的文本、表格、项目字段和说明文字必须回到当前招标文件格式检查，该填写的内容要补齐。
- 如果模块已经是成形大章节，通常直接作为 `group_final`。
- 如果模块只是一块局部内容，就不应误当完整大章节。
- 对反复出现的技术章节，如售后、质量、生产能力、制造工艺等，应先按产品类别或章节语义选模块，再替换项目字段和日期。

## Done 条件

- 模块来源、适用理由和输出作用域已回写。
- 原模块标题、编号、开头说明已对齐当前章节树。
- 当前项目格式已统一。
- 输出经过 DOCX 校验或渲染抽查。
