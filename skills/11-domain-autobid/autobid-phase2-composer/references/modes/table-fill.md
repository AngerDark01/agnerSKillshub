# Mode: table_fill

## 适用场景

- 招标文件已经给出明确表格模板。
- 表格结构应尽量保持不变。
- 本章核心工作是填值，而不是改写结构。

常见章节：`商务偏差表`、`技术偏差表`、`参数响应表`、`技术特性参数表`、`货物组件材料配置表`。

## 必读工具

- 表格读取：`../../../autobid-office-tools/references/docx-table.md`
- 写入段落或节点：`../../../autobid-office-tools/references/docx-write.md`
- 必要时定位模板：`../../../autobid-office-tools/references/docx-inspect.md`

## 标准动作

1. 从招标文件抽取原始表格模板。
2. 删除 `格式`、`模板`、`示例` 等提示标题，保留正式标题。
3. 显式读取格式规范并覆盖 section/layout。
4. 建立 `输出表字段 -> 来源字段` 映射。
5. 在原表中直接填值。
6. 保留必要空行，不随意裁剪结构。
7. 回写表格来源、字段映射和未决字段。

## 特殊规则

- 优先保留原表的行列逻辑，不因为填写方便而重做结构。
- 如果表里有二选一、条件分支，先做语义判断，再删不适用分支。
- 表格是最终交付格式的一部分，不要把它当中间数据结构随意重排。
- 涉及技术规范书回填时，必须先确认 `输出表字段 -> 源表字段` 的映射关系。
- 一张输出表允许来自多个源表或多个章节，最终仍以输出表结构为准。
- `投标人保证值` 这类承诺字段，在语义明确且无反证时，可与 `招标要求值` 保持一致，表示承诺满足。
- 必留但暂无值的行可以留空，不得因为缺值而删行。
- 项目名称、单位名称等长字段必要时可智能分行，优先保证成稿可读性。
- 对 `技术特性参数表`，默认按“编制说明 + 技术规范书参数表 + 输出模板”三方对齐后逐项回填。
- 对 `货物组件材料配置表`，如果输出表实际汇总了技术专项中的三张源表，必须三张都找齐再合并，不得只取其中一张。
- `必备的备品备件` 这类保底行在无值时保留空内容，不得删行。

## Done 条件

- 输出表保留招标文件要求的结构。
- 字段映射和来源已回写。
- 未决字段有 `pending_human`、`pending_asset`、`not_found` 或留空理由。
- 写入后已做 inspect 或渲染/校验检查。
