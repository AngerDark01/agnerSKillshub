# 投标人资格提取

## 目标

- 从“招标公告”的“投标人资格要求”章节生成一个独立 `docx`

## 基本判断

- 如果 `招标公告` 是独立 `docx`，直接处理这个文件
- 如果 `招标公告` 不独立，而是并在 `招标文件` 里，那么它就是完整招标文件的第一章
- 不管独立还是合并，资格提取都只先看“招标公告”这一章

## 输入

至少读取：

- `meta.分标名称`
- `meta.分标编号`
- `meta.包号`
- `files.招标公告`
- `files.招标文件`

## 任务隔离、等待与模型

- `qualifications` 默认由独立 subagent / 独立上下文执行，不与 `preschedule` 或 `scoring` 混做
- 开工时先只看当前文档列出的必读输入和工具文档，不预读 `phase2` 文档
- `qualifications` 通常是长任务；主代理等待该 subagent 时默认使用较长等待窗口，不因短超时或中间沉默提前回收
- 除非该任务已明确返回 `done`、`blocked` 或等价最终状态，否则不得关闭或回收该 subagent
- 除非用户明确指定模型，否则 `qualifications` 默认继承当前会话模型与推理档位，不硬性绑定具体模型名称

## 只看这些文档

先看：

- `../../autobid-office-tools/references/docx-inspect.md`
- `../../autobid-office-tools/references/docx-split.md`
- `../../autobid-office-tools/references/task-store.md`

如果资格要求里出现：

- `见附件`
- `见附表`
- `详见招标公告附件1`
- `见前附表`

就继续看：

- `phase1-preschedule-field-lookup.md`

## 执行步骤

### 1. 先确定“招标公告”范围

- 如果有独立 `招标公告.docx`，直接把它当作“第一章 招标公告”
- 如果没有独立公告，就在 `招标文件.docx` 里定位第一章“招标公告”的范围

### 2. 只在“招标公告”下面找资格要求

Agent 先做：

- `inspect(招标公告)` 或 `inspect(招标文件, body_range=第一章范围)`
- 列出“招标公告”这一章下面的子标题或子段落
- 找到标题为以下语义的范围：
  - `投标人资格要求`
  - `资格要求`
  - `投标人资质要求`

然后自己判断起止范围，直接拆这一段。

不要一开始就去第二章、第三章、第六章找一堆相关内容。

### 3. 检查这一段里有没有引用

重点看有没有这类句子：

- `详见招标公告附件1`
- `见附件`
- `见附表`
- `见前附表`
- `详见专用资质业绩要求`

如果没有引用：

- 直接把这一段做成独立 `docx`

如果有引用：

- 不要把附件或附表直接带出来
- 按 `phase1-preschedule-field-lookup.md` 的方式继续查真实内容

### 4. 如果引用落在附件或附表里

处理原则只有一个：

- 根据 `分标名称 / 分标编号 / 包号` 找当前项目对应的信息

禁止做的事：

- 禁止把整个附件带出来
- 禁止把整个附表带出来
- 禁止把整张表带出来

正确做法：

- 只取当前分标、当前包号对应的信息
- 把这部分内容回填到主文档里

也就是说：

- 最终交付件里只保留“资格要求正文 + 当前包对应的被引用内容”
- 不保留附件页
- 不保留附表页

### 5. 输出结果

最终只输出一个主文件：

- `output.资格要求汇编.docx`

要求：

- 是独立 `docx`
- 内容完整
- 不带任何附件
- 不带任何附表
- 不带其他包号内容
- 不带无关章节

## 回写 store

至少写回：

- `qualifications.source_ranges`
- `qualifications.items`
- `qualifications.pending`
- `output.资格要求汇编`
