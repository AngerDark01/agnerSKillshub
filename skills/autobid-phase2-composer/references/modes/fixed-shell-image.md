# Mode: fixed_shell_image

## 适用场景

- 章节由固定标题壳、固定说明和一张或多张图片/扫描件组成。
- 材料核心在图片本身，AI 只负责壳子和挂载。

常见章节：`营业执照扫描件`、`银行基本账户证明扫描件`、`检测报告截图`、`认证证书`。

## 模板来源

1. 当前招标文件切片。
2. `Data/modules/` 或资料库中的可复用 DOCX。

## 必读工具

- 模板定位：`../../../autobid-office-tools/references/docx-inspect.md`
- 带图片关系合并：`../../../autobid-office-tools/references/docx-merge.md`
- 版式复制：`../../../autobid-office-tools/references/docx-layout.md`
- 打包校验：`../../../autobid-office-tools/references/docx-pack.md`

## 标准动作

1. 先按章节语义选模板，不按文件名机械套用。
2. 判断本章是独立章节还是大章节内部子节点。
3. 按需要产出 `single_chapter` 或 `child_partial`。
4. 对图片主体优先直接复用原图、原关系和原拼接结构。
5. 对壳子标题、说明文字和项目字段做当前项目适配。
6. 统一当前项目格式。
7. 最终由大章节或总稿完成关系级拼接。

## 特殊规则

- 对敏感扫描件，只处理外层壳和格式，不主动分析图片内容。
- 如果模板本身就是大块图片拼接出来的 DOCX，不要把图片重新拆写成低保真排版。
- 如果模块只覆盖子章节正文，不要机械把父标题补进每个子章节文件。
- 同组 sibling 中间如果有节点被删除，后续保留节点要连续重编号。
- 模板套用后，仍然要动态调整章节号、标题、说明文字和项目格式。
- 如果同一章同时需要表格信息和贴图证明，优先拆成 `信息表 partial` 与 `贴图 partial` 再组装。
- 存在产品类别差异时，应先选对贴图模板或附件模板，再挂具体材料。

## Done 条件

- 图片、扫描件或附件来源已记录。
- 关系文件和媒体文件未丢失。
- 壳子标题和说明已适配当前章节树。
- 输出经过 pack/validate 或渲染检查。
