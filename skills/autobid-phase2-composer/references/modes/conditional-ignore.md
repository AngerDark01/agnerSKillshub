# Mode: conditional_ignore

## 适用场景

- 招标文件明确写明“无需提交”“本次不适用”“按条件提交”。
- 当前项目条件不满足，章节不应进入最终正文。

常见章节：明确写明无需提交的保证金材料、本项目不适用的可选证明文件、按条件提交但当前条件不触发的章节。

## 标准动作

1. 找到“不适用”或“无需提交”的依据。
2. 判断是直接删除，还是保留空位/说明。
3. 在元数据中记录删除原因或留空原因。
4. 同步处理同组节点的重编号影响。
5. 回写章节树和 task store。

## 特殊规则

- 不能因为缺资料就直接当作 `conditional_ignore`。
- `conditional_ignore` 必须有明确来源依据。
- 如果招标文件要求“保留章节但留空”或“保留标题并说明”，就不能直接删章节。
- 用户已确认的不适用结论，必须同步回写章节树和 task store。

## Done 条件

- 不适用依据已记录。
- 删除、留空或保留说明的处理方式已明确。
- 同组章节编号影响已同步。
- 下游组装不再等待该节点正文。
