# 本体核心概念速查

| 概念 | 解释 | 类比 |
|------|------|------|
| **T-Box** | 类/术语层，定义概念、关系、公理（Schema，设计时） | 数据库的表结构定义 |
| **A-Box** | 实例层，具体的对象数据（Data，运行时） | 数据库里的每一行记录 |
| **Class（类）** | 一类事物的抽象定义，如"客户"、"订单" | 数据库的表 |
| **Instance（实例）** | 某个类的具体成员，如"客户-张三" | 数据库的一行 |
| **Object Property** | 连接两个类的关系，如 `assignedTo: WorkItem → Person` | 外键，但有语义方向 |
| **Datatype Property** | 连接类与具体值，如 `hasStatus: WorkItem → string` | 普通字段 |
| **Object Type** | 业务实体类型，背后绑定真实数据源，实时同步 | 有"生命"的表 |
| **Link Type** | 实体间有语义的关系，支持导航和推理 | 带语义的外键 |
| **Transitivity（传递性）**| 公理：A→B, B→C 自动推导 A→C | 无需手写递归 |
| **Disjointness（互斥）** | 公理：两个类不能被同一实例同时归属 | 约束检查 |
| **Cardinality（基数）** | 约束关系的数量，如"恰好 1 个 author" | NOT NULL + UNIQUE |
| **Domain/Range** | 属性的起点类（Domain）和终点类/值类型（Range） | 外键的两端表 |
| **Function / Logic** | 可执行的业务逻辑，只读不写，是"思考"单元 | 数据库视图/存储过程（只读） |
| **Action** | 受控的写操作，带参数/验证/权限/审计 | 带权限控制的 API 端点 |
| **Kinetic 层** | 将底层数据映射到本体对象的连接层 | ORM / ETL |
| **OSDK** | 本体的代码操控 SDK，供外部系统调用 | REST SDK |
| **CQ（Competency Question）**| 能力问题，建模前用于界定本体边界的核心查询 | 验收测试用例 |
| **OWA（开放世界假设）** | 未记录的事实是"未知"而非"不存在" | 本体采用此假设 |
| **CWA（封闭世界假设）** | 未记录的事实即"不存在" | 数据库采用此假设 |
| **推理机（Reasoner）** | 根据公理自动推导隐含事实的引擎 | 如 HermiT、Pellet |
| **SPARQL** | 本体的查询语言，类似 SQL 但面向图结构 | SQL for graphs |
| **Turtle（.ttl）** | 本体最常用的序列化格式，人类可读 | JSON/XML for ontology |

## 常见误区

**误区 1**：本体 = 知识图谱
> 知识图谱描述关系，本体还能**推理**关系并**执行操作**。

**误区 2**：有 Object + Link 就够了
> 缺少 Logic/Action 的只是"骨架"，完整本体还需要可执行规则和受控操作。

**误区 3**：先建模，再想用途
> 必须先定 CQs，再建模。没有 CQ 的建模会无限膨胀。

**误区 4**：传递性关系要手动录入所有路径
> 公理声明后，推理机自动展开，只需录入直接关系。
